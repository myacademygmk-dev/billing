Open Website Changes

1. Website Feature Parity Is Partial

The public website still needs richer school-site content beyond the core pages. Remaining gaps include video gallery depth, student sections, management content, academics content, class timetable display, quick links, social links, contact details in the header, payment terms, and publications.

Medium

2. Homepage Needs Content Blocks From Existing Pages

Achievements, gallery photos, latest dated news/events, admissions callouts, and student highlights should be surfaced on the homepage so users do not need to discover everything through navigation.

Medium

3. Public Form Validation Needs Hardening

Public enquiry and alumni forms need stronger semantic validation, duplicate/spam handling, rate limiting verification, and clear error states. These forms are public entry points and should be treated as abuse-prone.

High

4. Website Workflow Tests Are Missing

Add tests for public navigation, enquiry submission, alumni registration, gallery rendering, CMS-driven homepage data, and failure states when public APIs are unavailable.

Medium

Website Vulnerability Watch

Public Form Abuse

Risk: enquiry and alumni endpoints can receive spam or repeated submissions. Track rate limiting, duplicate detection, field length limits, and server-side validation for every public form.

Stored Content Injection

Risk: CMS-managed text, captions, announcements, testimonials, alumni data, and embedded links can become stored XSS if rendered unsafely. Track all places where CMS strings or JSON fields reach public pages.

Upload Safety

Risk: website images/PDFs are public files. Track size limits, MIME/extension matching, allowed file types, generated filenames, database-backed serving, and path containment.

External Video Links

Risk: video URLs from website config can point to unexpected domains or embed untrusted content. Track allowlisting for YouTube URLs and frontend handling for invalid links.

Public Data Exposure

Risk: public APIs should only return publishable website data. Track response fields for student creativity, testimonials, alumni content, gallery, and institution config to avoid leaking internal IDs or private data.

SEO And Metadata Gaps

Risk: missing metadata is not a security bug, but it affects website quality. Track page titles, descriptions, canonical URLs, Open Graph data, and image alt text for public pages.
